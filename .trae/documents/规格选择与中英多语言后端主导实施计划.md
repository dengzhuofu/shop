# 规格选择与中英多语言后端主导实施计划

## Summary
- 目标：从后端视角重构“SKU 规格选择 + 中英文多语言”方案，确保商品详情、购物车、结算、订单全链路一致。
- 结论方向：采用“后端主导多语言 + 结构化规格协议 + 一次性脚本迁移”。
- 成功标准：
  - 详情页稳定显示 `Style/Bundle/Color`（或对应中文），并能正确映射 `skuId`。
  - 购物车/结算/订单使用同一套规格展示字段，不再出现 `[object Object]` 或空规格。
  - 仅支持中英文，语言切换由后端按 `lang` 输出业务文案，前端只负责UI层文案。

## Current State Analysis

### 1) 规格设计现状（可用但不稳定）
- SKU 原始规格存储在 `pms_sku.specs(JSONB)`，当前历史数据存在两种形态并存：
  - 扁平对象（如 `{"style":"...","bundle":"..."}`）
  - 多语言对象（如 `{"zh":{...},"en":{...}}`）
- 后端已做归一化入口，但链路仍不统一：
  - [SkuVO.java](file:///e:/project/shop/backend/src/main/java/com/shop/vo/SkuVO.java) 输出 `specs + attributes`
  - [ProductVO.java](file:///e:/project/shop/backend/src/main/java/com/shop/vo/ProductVO.java) 聚合 `skuAttributeOptions`
  - 购物车/订单快照仍大量写入 `sku.getSpecs()` 原始结构（非统一协议）

### 2) 多语言现状（机制存在但执行不一致）
- 后端有语言上下文机制：`LanguageInterceptor -> LanguageContext`。
  - [LanguageInterceptor.java](file:///e:/project/shop/backend/src/main/java/com/shop/config/LanguageInterceptor.java)
  - [LanguageContext.java](file:///e:/project/shop/backend/src/main/java/com/shop/common/LanguageContext.java)
- 前端仍存在写死 `lang=en` 的请求点，导致语言策略漂移：
  - [pages/index.vue](file:///e:/project/shop/pages/index.vue)
  - [pages/products/[id].vue](file:///e:/project/shop/pages/products/[id].vue)
- 购物车/订单标题部分逻辑未完全走语言上下文，存在中英切换不一致风险。

### 3) 当前设计合理性判断（后端视角）
- “前端自行根据当前语言切文本”不适合作为主方案，原因：
  - 订单/快照是业务审计数据，应由后端产出确定性展示字段；
  - 前端多入口（详情、侧栏、checkout、订单页）各自解析会增加偏差；
  - 同一 SKU 在不同页面被不同解析器处理，容易出现显示不一致。
- 因此应采用：**后端主导业务文案与规格展示值**，前端仅消费标准化字段。

## Proposed Changes

### A. 规格与多语言统一协议（核心）
- 目标文件：
  - [SkuVO.java](file:///e:/project/shop/backend/src/main/java/com/shop/vo/SkuVO.java)
  - [ProductVO.java](file:///e:/project/shop/backend/src/main/java/com/shop/vo/ProductVO.java)
  - 新增 `SkuAttributeVO`（建议）
- 协议统一为：
  - `sku.attributes`：机器可匹配键值（`style/bundle/color`）
  - `sku.attributeDisplay`：当前语言展示值（后端按 `lang` 生成）
  - `product.skuAttributeOptions`：供前端渲染选项，按统一键返回
- 约束：
  - 对外不再依赖 `specs` 的多形态解析；`specs` 仅保留内部兼容期使用。

### B. 链路统一到“同一规格来源”
- 目标文件：
  - [CartController.java](file:///e:/project/shop/backend/src/main/java/com/shop/controller/CartController.java)
  - [OmsOrderServiceImpl.java](file:///e:/project/shop/backend/src/main/java/com/shop/service/impl/OmsOrderServiceImpl.java)
  - [OrderItemVO.java](file:///e:/project/shop/backend/src/main/java/com/shop/vo/OrderItemVO.java)
- 变更策略：
  - 购物车快照、订单项快照改为保存统一结构（`attributes + attributeDisplay + lang`）。
  - 预览/订单查询统一输出快照字段，前端不再做对象猜测或 `Object.values` 拼接。

### C. 中英多语言职责边界（后端主导）
- 后端职责：
  - 按 `lang` 输出商品标题、SKU展示值、规格label/value、订单展示文案字段。
  - 默认回退策略：`lang -> en -> zh`（不可空）。
- 前端职责：
  - 仅持有当前语言状态并传递到请求（query/header二选一，统一实现）。
  - UI固定文案（按钮、标题）仍走前端 i18n。
- 目标文件：
  - [useHttp.ts](file:///e:/project/shop/composables/useHttp.ts)
  - [pages/index.vue](file:///e:/project/shop/pages/index.vue)
  - [pages/products/[id].vue](file:///e:/project/shop/pages/products/[id].vue)
  - [pages/checkout.vue](file:///e:/project/shop/pages/checkout.vue)

### D. 一次性历史数据迁移脚本
- 目标文件：
  - [mock_data_cleanup.sql](file:///e:/project/shop/backend/src/main/resources/mock_data_cleanup.sql)
  - [mock_data_insert.sql](file:///e:/project/shop/backend/src/main/resources/mock_data_insert.sql)
  - 新增 `sku_i18n_migration.sql`（建议）
- 脚本任务：
  - 扫描 `pms_sku.specs` 历史形态，统一转为标准结构；
  - 回填购物车/订单历史快照为统一协议；
  - 生成异常报告（缺 style/bundle/color 的 SKU 列表）。

### E. 前端详情页显示兜底（迁移期）
- 目标文件：
  - [pages/products/[id].vue](file:///e:/project/shop/pages/products/[id].vue)
- 迁移期规则：
  - 优先消费后端标准字段 `skuAttributeOptions + attributes`；
  - 仅保留最小兼容兜底（历史字段读取），并设置移除时间点。

## Assumptions & Decisions
- 只做中英文，不扩展更多语言。
- 采用后端主导业务多语言输出，前端不做业务值翻译。
- 规格数据目标协议为“结构化 + 多语言展示值”。
- 历史数据采用一次性 SQL 脚本迁移，不走长期双轨兼容。

## Verification Steps

### 1) 接口一致性验证
- `GET /product/{id}?lang=zh` 与 `lang=en` 返回：
  - `skuAttributeOptions` 完整且键统一（style/bundle/color）
  - `sku.attributes` 稳定可匹配
  - `sku.attributeDisplay` 随语言变化
- `GET /cart/list`、`POST /order/preview`、`GET /order/{id}`：
  - 规格展示字段结构一致，跨页面同值同序。

### 2) 前端行为验证
- 详情页选择不同规格，按钮区和加购请求 `skuId` 与选项严格一致。
- 购物车侧栏、checkout、订单页显示的规格文本与当前语言一致。
- 语言切换后刷新页面，规格展示无空白、无 `[object Object]`。

### 3) 数据迁移验证
- 执行迁移脚本后，抽检旧 SKU、购物车、订单项快照：
  - 无缺失关键键（style/bundle/color）
  - 无非法 JSON 结构
  - 语言回退策略生效。

### 4) 回归与构建
- 后端：`mvn test` 通过。
- 前端：`npm run build` 通过。
- 关键链路：浏览商品 → 选规格 → 加购/直结 → 支付 → 订单查看。
