# 后端接口与前端对接计划

## 现状分析

### 后端已完成的接口 (端口: 8080)
| Controller | 接口路径 | 方法 | 描述 | 鉴权 |
|------------|---------|------|------|------|
| AuthController | `/auth/login` | POST | 用户登录 | 否 |
| AuthController | `/auth/logout` | POST | 用户登出 | 是 |
| ProductController | `/product/list` | GET | 商品列表(分页) | 否 |
| ProductController | `/product/{id}` | GET | 商品详情 | 否 |
| CartController | `/cart/add` | POST | 加入购物车 | 是 |
| CartController | `/cart/list` | GET | 购物车列表 | 是 |
| OrderController | `/order/create` | POST | 创建订单 | 是 |
| OrderController | `/order/list` | GET | 订单列表 | 是 |
| OrderController | `/order/{id}` | GET | 订单详情 | 是 |
| OrderController | `/order/{id}/cancel` | PUT | 取消订单 | 是 |
| ReviewController | `/review/product/{id}/summary` | GET | 评论摘要 | 否 |
| ReviewController | `/review/product/{id}` | GET | 评论列表 | 否 |

### 前端问题
1. 登录页面调用错误的接口：`/api/user/login` → 应为 `/auth/login`
2. 缺少 API 代理配置，前端无法正确转发请求到后端
3. 前端直接使用 `http://localhost:8080` 硬编码，不适合生产环境

---

## 对接步骤

### 第1步：修复登录接口对接
- [ ] 修改 `pages/login.vue` 中的 API 调用路径
- [ ] 从 `/api/user/login` 改为 `/api/auth/login`（通过代理）

### 第2步：配置 Nuxt API 代理
- [ ] 在 `nuxt.config.ts` 中添加 nitro proxy 配置
- [ ] 将 `/api/auth` 代理到 `http://localhost:8080/auth`
- [ ] 将 `/api/product` 代理到 `http://localhost:8080/product`
- [ ] 将 `/api/cart` 代理到 `http://localhost:8080/cart`
- [ ] 将 `/api/order` 代理到 `http://localhost:8080/order`
- [ ] 将 `/api/review` 代理到 `http://localhost:8080/review`

### 第3步：统一前端 API 调用方式
- [ ] 创建 `composables/useApi.ts` 或在 nuxt.config 中统一配置
- [ ] 移除前端各页面中的硬编码 `http://localhost:8080`

### 第4步：测试登录接口
- [ ] 启动后端服务
- [ ] 启动前端服务
- [ ] 测试登录功能是否正常

## 实施细节

### nuxt.config.ts 代理配置
```typescript
nitro: {
  prerender: {
    failOnError: false,
  },
  proxy: {
    '/api/auth': 'http://localhost:8080/auth',
    '/api/product': 'http://localhost:8080/product',
    '/api/cart': 'http://localhost:8080/cart',
    '/api/order': 'http://localhost:8080/order',
    '/api/review': 'http://localhost:8080/review',
  }
}
```

### pages/login.vue 修改
```typescript
// 修改前
const response = await $fetch('/api/user/login', { ... })

// 修改后
const response = await $fetch('/api/auth/login', { ... })
```

## 注意事项
1. 登录成功后需要将 token 保存到 cookie 或 localStorage
2. 后续请求需要在请求头中携带 Authorization token
3. Sa-Token 的 token-name 配置为 "Authorization"
