# 完善商品浏览到支付全链路接口计划

## 一、Summary
- 目标：打通“商品浏览 → 商品详情 → SKU规格选择与数量 → 加入购物车/直接结算 → 下单 → Mock支付确认”的完整接口链路，并确保前端页面字段与数据库字段一一对应。
- 范围：本期包含数据库结构调整、后端接口改造、前端字段对齐重构（不做新旧双兼容），仅支持登录用户结算。
- 设计决策：
  - 支付层采用 Mock 支付确认；
  - SKU 规格统一改为结构化 `attributes`；
  - 数据库变更通过脚本执行（支持插入/删除/重建）。

## 二、Current State Analysis

### 2.1 现有前端链路（已确认）
- 商品浏览已调用商品列表接口：`GET /api/product/list`（首页）。
- 商品详情页已调用详情与评论接口，但存在字段解析不一致：
  - `quickKnow` 当前前端按 JSON 解析；
  - `sku.specs` 当前前端按 JSON 字符串解析并依赖 `.en.Style/.en.Bundle`。
- 加购接口已调用：`POST /api/cart/add`，但 `skuId` 在前端写死为 `1`，未按规格选择映射。
- 购物车侧栏只拿到 `productId/skuId/quantity`，缺少商品名、图片、单价等展示字段。
- 结算页当前主要是 Mock UI，尚未对接下单与支付接口。

### 2.2 现有后端与数据库（已确认）
- 已有核心表：`pms_product`、`pms_sku`、`oms_cart_item`、`oms_order`、`oms_order_item`。
- 已有核心接口：
  - 商品：`/product/list`、`/product/{id}`
  - 购物车：`/cart/add`、`/cart/list`
  - 订单：`/order/create`、`/order/list`、`/order/{id}`、`/order/{id}/cancel`
- 主要缺口：
  - 缺失地址模型与地址接口；
  - 缺失支付确认接口；
  - 下单 DTO 仅 `cartItemIds`，无法承载地址/配送/支付方式；
  - 购物车列表返回体信息不足，无法直接驱动结算与侧栏展示；
  - SKU 规格输出结构与前端选择逻辑不一致。

## 三、Proposed Changes

### 3.1 数据库层（schema + 脚本）
- 文件：
  - `backend/src/main/resources/schema.sql`
  - `backend/src/main/resources/mock_data_insert.sql`
  - 新增：`backend/src/main/resources/mock_data_cleanup.sql`（删除/重置脚本）
- 变更内容：
  1. 新增用户地址表（建议 `ums_user_address`）：
     - 字段：`id,user_id,country,first_name,last_name,phone,address_line1,address_line2,city,state,zip_code,is_default,created_time,updated_time`
  2. 扩展订单表 `oms_order`：
     - 新增地址快照字段：`receiver_country,receiver_first_name,receiver_last_name,receiver_phone,receiver_address_line1,receiver_address_line2,receiver_city,receiver_state,receiver_zip_code`
     - 新增支付相关字段：`payment_method,pay_status,pay_time,pay_txn_no`
     - 新增流程标记：`checkout_source`（cart/direct）
  3. 扩展订单项 `oms_order_item`：
     - 新增 `sku_attributes_snapshot`（JSON，保存下单时规格快照）
  4. 可选扩展购物车 `oms_cart_item`：
     - 新增 `selected_attributes_snapshot`（若要加速回显）
  5. 更新 mock 数据脚本：
     - 插入覆盖：商品、SKU、地址、购物车、订单/订单项；
     - 保证至少一组可完整演示“有地址自动回填 + SKU可选 + 下单 + 支付”。

### 3.2 后端领域模型与传输对象
- 文件：
  - `backend/src/main/java/com/shop/entity/*`
  - `backend/src/main/java/com/shop/dto/*`
  - `backend/src/main/java/com/shop/vo/*`
- 变更内容：
  1. 商品/SKU 输出标准化：
     - `SkuVO` 新增结构化 `attributes`（如 `{"style":"S9 Pro","bundle":"Standard","color":"Black"}`）；
     - `ProductVO` 对齐 `quickKnow` 为数组/对象结构（不再依赖前端 JSON.parse 字符串）。
  2. 购物车返回 VO 化（不再直接返 Entity）：
     - 新增 `CartItemVO`：`cartItemId,productId,skuId,title,productPic,unitPrice,quantity,lineAmount,attributes,stock`
  3. 下单与支付 DTO/VO 完整化：
     - `OrderCreateDTO` 扩展：`source(cart/direct),items/addressId|addressSnapshot,paymentMethod,shippingMethod,remark`
     - `OrderPayDTO`：`orderId,paymentMethod,mockResult`
     - `OrderVO` 扩展支付与地址快照字段，统一前端订单页与支付结果页可读。
  4. 地址 DTO/VO：
     - `AddressCreateDTO`、`AddressUpdateDTO`、`AddressVO`。

### 3.3 后端接口层（Controller + Service）
- 文件：
  - `backend/src/main/java/com/shop/controller/ProductController.java`
  - `backend/src/main/java/com/shop/controller/CartController.java`
  - `backend/src/main/java/com/shop/controller/OrderController.java`
  - 新增 `backend/src/main/java/com/shop/controller/AddressController.java`
  - 对应 `service/*` 与 `service/impl/*`
- 变更内容：
  1. 商品接口
     - `GET /product/list`：保证列表字段与前端卡片字段一致（`id,title,price,compareAtPrice,pic,tags`）。
     - `GET /product/{id}`：返回结构化 SKU attributes、可选规格集合与默认 SKU。
  2. 购物车接口完善
     - 保留：`POST /cart/add`
     - 新增：`PUT /cart/{id}`（改数量）、`DELETE /cart/{id}`（删项）
     - `GET /cart/list` 返回 `CartItemVO`，供侧栏和结算页直接使用。
  3. 地址接口（登录态）
     - `GET /address/list`
     - `POST /address`
     - `PUT /address/{id}`
     - `DELETE /address/{id}`
     - `PUT /address/{id}/default`
  4. 订单/结算接口
     - `POST /order/preview`：按 cart/direct 输入返回金额试算（商品、运费、折扣、总额）
     - `POST /order/create`：创建待支付订单（保存地址快照与 SKU 快照）
     - `POST /order/pay`：Mock 支付确认，更新 `pay_status/pay_time/pay_txn_no/order_status`
     - 保留并对齐：`GET /order/list`、`GET /order/{id}`、`PUT /order/{id}/cancel`

### 3.4 前端字段对齐改造
- 文件：
  - `pages/index.vue`
  - `pages/products/[id].vue`
  - `components/CartSidebar.vue`
  - `pages/checkout.vue`
  - `pages/account/orders.vue`
  - `pages/account/profile.vue`
  - `components/AddAddressModal.vue`
  - `composables/useHttp.ts`（若需统一错误处理/类型）
- 变更内容：
  1. 商品详情页
     - 移除对 `quickKnow`、`sku.specs` 的 JSON.parse 依赖；
     - 按 `attributes` 建立规格选中状态到 `skuId` 的映射；
     - 加购时使用真实选中 `skuId` 与 `quantity`。
  2. 购物车侧栏/结算页
     - 改为消费 `CartItemVO`，展示标题、图片、属性、价格、小计；
     - 结算页默认地址回填改为真实 `GET /address/list` 默认项。
  3. 订单流
     - 新增“直接结算”分支（从详情页带选中 SKU+数量进预结算）；
     - 下单调用 `order/create`，支付按钮调用 `order/pay` Mock 确认；
     - 订单页读取真实订单列表。

### 3.5 Mapper 与查询优化
- 文件：
  - `backend/src/main/java/com/shop/mapper/*`
  - 可能新增 XML/注解查询（按项目现状）
- 变更内容：
  - 为购物车列表、订单详情增加联表/批量查询，避免 N+1；
  - 保证库存校验、价格快照、SKU有效性校验在下单时生效。

## 四、Assumptions & Decisions
- 仅支持登录用户结算，不实现游客结算。
- 接口重构采用“新结构直切”，不保留旧字段解析兼容。
- 支付为 Mock 成功/失败两种结果，不接入第三方支付网关。
- 数据库变更以 SQL 脚本为准，可直接执行插入/删除/重建。
- 语言维度按现有 `lang` 机制继续保留，但 SKU 规格核心字段统一结构化。

## 五、Implementation Steps
1. 先完成数据库脚本调整（建表、加列、mock 插入与清理脚本）。
2. 更新 Entity/DTO/VO，先稳定统一数据模型。
3. 改造 Product/Cart/Order 服务与控制器，补齐 AddressController 与支付接口。
4. 联调前端关键页面字段（详情 SKU 选择、购物车、结算、订单、地址弹窗）。
5. 执行端到端自测：浏览→详情选规格→加购/直结→下单→Mock支付→订单查询。

- 编译与启动：
  - 后端 `mvn test` / `mvn -DskipTests=false test`（按现有项目命令）

- 接口验证（至少覆盖）：
  1. 商品列表/详情返回字段与前端读取字段一致；
  2. SKU 规格选择可稳定映射到正确 `skuId`；
  3. 加购、改数量、删项后购物车金额正确；
  4. 地址新增/编辑/默认设置可用于结算自动回填；
  5. 预结算金额、下单金额、支付后订单状态一致；
  6. 订单列表与详情可展示地址和 SKU 属性快照。
- 回归重点：
  - 详情页不再出现 JSON.parse 结构错误；
  - checkout 从“纯 Mock 展示”变为真实接口驱动；
  - 订单页从空态切换为真实数据展示（有数据时）。
